# Genesis AI Roles

## Назначение

Роли, полномочия и зоны ответственности. Исполнитель роли (человек / ИИ / инструмент) может меняться; обязанности роли сохраняются.

**Канон:** этот файл в `governance/Roles.md`.

---

## CEO

**Исполнитель:** человек — владелец проекта.

- цели и приоритеты;
- окончательные решения;
- Execution Authorization и Merge Authorization;
- утверждение Specification и scope.

Может останавливать задачи, назначать исполнителей, менять стратегию.

---

## COO

**Исполнитель:** ChatGPT.

- удерживает процессный контекст с CEO;
- координирует роли;
- анализ, process review, постановка шагов;
- помогает с ACTIVE.md / MEMORY.md (содержательно).

**Ограничение:** GitHub write **недоступен** этому исполнителю. Не выполняет commit/PR/merge самостоятельно.

---

## Chief Architect

**Исполнитель:** Grok.

- независимая архитектурная оценка и dissent / Stop the Line;
- review Git-артефактов;
- исполнение **документационных и технических** изменений в GitHub **только** в пределах явного CEO Authorization;
- не утверждает собственную реализацию как единственный independent reviewer той же работы.

На текущем этапе закрывает архитектурные обязанности, пока постоянный CTO не выбран.

---

## CTO

**Статус:** постоянный исполнитель **не назначен**.

Отбор — задачи T-002…T-005 (BACKLOG в `bridge/QUEUE.md`).

**Устарело:** «ChatGPT временно исполняет CTO» больше **не** является оперативным статусом. ChatGPT действует как **COO**.

Когда CTO будет назначен Decision Record’ом, обязанности архитектуры/рисков уточняются относительно Chief Architect.

Целевые обязанности роли CTO (после назначения):

- перевод целей CEO в технические решения;
- архитектура и риски;
- согласованность системы;
- не подменять стратегические решения CEO.

---

## Lead Engineer (GitHub Engineer)

**Исполнитель:** GitHub Copilot (DR-0002).

- реализация утверждённых задач через Issue → branch → PR;
- не меняет Constitution / strategy / Roles / DR без прямого CEO permission;
- не принимает архитектурные решения самостоятельно.

---

## Developer

Исполнитель: Cursor, Codex, другой агент или человек.

Реализация в рамках задания; без самовольной смены целей/архитектуры.

---

## QA / Research / Documentation

- **QA** — проверка соответствия заданию; не «чинит молча».
- **Research** — факты и сравнения; не принимает решения.
- **Documentation** — актуальность документов; часть продукта.

---

## Repository

**Исполнитель:** GitHub — единый источник истины (SoR).

---

## Порядок взаимодействия (упрощённо)

1. CEO задаёт цель / Authorization.
2. COO структурирует процесс; Chief Architect оценивает риски.
3. Specification + EA по Development Workflow.
4. Lead Engineer / Developer реализуют в PR.
5. Independent review (не автор в одиночку).
6. CEO Merge Authorization → merge → Bridge update.

---

## Правило ответственности

У каждой задачи: владелец решения, исполнитель, критерий готовности, проверка. ИИ не снимает ответственность CEO.
